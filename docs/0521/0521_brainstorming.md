# 브레인스토밍
- 개발중 발생한 문제들을 토대로 어떻게 더 개선할 수 있을지 생각해보자

## 기존 방식
- 각 목적지에 대응하는 qr코드를 여러개 발행

## 개선 방식
- qr코드에 대응하는 db를 관리하는 서버를 활용해 qr코드 개수를 줄인다

## 기대효과
- qr코드 개수 감소 -> 오인식 확률 감소
- 서버 대시보드를 통해 병실 정보의 추가, 삭제, 수정이 용이
- 웹 대시보드를 통해 실시간 시각화



## 실행 계획
1. DB 구조 정리
    - 현재 테이블 구조
    - 테이블 추가 및 변경안
        - status 컬럼: 대기, 이동중, 도착, 기타(오류, 배터리 부족 등)
2. DB 수정
    - 수정된 테이블로 DB 생성
    - DB 내용 확인

## 테스트 시나리오
- 출발지점과 목적지의 qr코드를 db로 관리하기 때문에, 도착지에서도 도착지점의 qr코드를 스캔해 도착 확인 정보만 발행하면 충분하다고 판단
- 출발 지점에서 qr코드로 도착 지점 좌표를 읽어 목적지에 도달 후, 도착 qr 코드를 스캔하면 orders 테이블의 status 컬럼을 done으로 변경
- 이후 로봇은 자동으로 출발 지점으로 이동하여 qr코드를 5초마다 스캔, 대기중인 작업을 찾으면 해당 작업으로 다시 출발
