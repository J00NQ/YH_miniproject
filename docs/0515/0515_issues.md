# 1회차 미니프로젝트 진행 중 발생한 이슈 및 해결 과정

## [이슈 1] VMWare 가상환경으로의 대용량 파일/이미지 전송 오류
* **상황**: 호스트 OS(Windows)에서 게스트 OS(VMWare Ubuntu)로 병원 월드의 3D 모델 파일 및 텍스처 이미지(`*.dae`, `*.jpg`)를 드래그 앤 드롭으로 복사하려 할 때, 제대로 전송되지 않거나 전송이 멈추는 현상 발생.
* **원인**: VMWare Tools의 클립보드/드래그 앤 드롭 기능은 텍스트나 소규모 파일에는 잘 동작하지만, 복잡한 디렉토리 구조나 이미지/바이너리 파일을 한 번에 여러 개 복사할 때 종종 버그(Timeout, 파일 깨짐 등)를 일으킵니다.
* **해결 방안**:
  > **안내**: VMWare Tools가 설치되지 않아 드래그 앤 드롭 자체가 불가능한 경우, [VMWare 파일 전송 및 동기화 가이드](../0515/0515_vmware_sync_guide.md) 문서를 참고하여 SSH 서버나 Tools를 먼저 설치해 주세요.

  1. **단일 압축 파일(ZIP)로 묶어서 전송**: 여러 파일과 폴더를 통째로 옮기지 말고, 호스트 측에서 폴더를 `.zip` 파일로 압축한 뒤 해당 **압축 파일 딱 1개**만 드래그 앤 드롭하여 VMWare로 넘깁니다. 이후 Ubuntu 터미널에서 `unzip` 명령어로 압축을 해제합니다. (가장 간편하고 에러 확률이 낮음)
  2. **Git을 활용한 동기화 (권장)**: 윈도우 환경의 코드(문서, 모델 포함)를 Github 등의 원격 저장소에 `push`하고, VMWare 환경에서 `git pull`을 통해 내려받습니다. 바이너리 파일도 가장 안전하게 동기화할 수 있는 실무적인 방법입니다.
  3. **Python 로컬 서버 활용**: 윈도우 터미널에서 `python -m http.server 8000`을 열고, VMWare 인터넷 브라우저나 `wget` 명령어로 다운로드합니다.
  4. **SSH (SCP) 전송**: 우분투에 SSH 서버를 설치하고 윈도우 터미널에서 `scp` 명령어나 `FileZilla` 등을 활용하여 네트워크로 파일을 쏩니다.

## [이슈 2] 데이터 과부하(고밀도 JSON)로 인한 작은 QR 코드 인식 실패
* **상황**: 로봇 카메라에서 `0.2 x 0.2` 크기의 작은 QR 코드를 바라볼 때 비전 인식 노드(`pyzbar`)가 코드를 해독하지 못하는 문제 발생.
* **원인**: 
  1. 기존의 AIHub 기반 JSON 포맷(`taskId`, `taskName`, `target` 등)의 길이가 길어 QR 코드가 고밀도(Version 상승)로 생성됨.
  2. 가제보 내 로봇 카메라 해상도 한계 상, 20cm의 작은 면적 안에 빼곡하게 밀집된 점(픽셀)들이 뭉개져(Aliasing) 회색조로 보임.
  3. `vision_recognizer_node.py`의 `GaussianBlur` 전처리까지 더해져 흑백 경계가 완전히 손실됨.
* **해결 방안**: (물리적 QR 크기 확대 대신 입력 데이터 경량화 선택)
  1. `generate_qr_models.py`에서 JSON 키 값을 최소화(`id`, `tgt`, `ARR` 등)하여 문자열 길이를 대폭 축소, QR 코드 내 모듈(점)의 크기를 물리적으로 키움.
  2. 가제보 모델의 크기는 기존 기획대로 `0.2` 스케일 유지.
  3. 데이터 포맷 변경에 맞춰 `vision_recognizer_node.py` 및 `path_planner_node.py`의 파싱 로직 동기화 업데이트.

## [이슈 3] 인식 거리 부족으로 인한 QR 코드 인식 실패

* **상황**: 이슈 2의 데이터 경량화 및 전처리 개선 이후에도 `pyzbar`가 QR 코드를 여전히 인식하지 못함. 로봇과 QR 코드 사이의 거리를 줄였을 때 정상 인식됨.

* **원인 분석**:
  1. **카메라 해상도 대비 픽셀 점유 면적 부족**: Gazebo 시뮬레이터 내 TurtleBot3의 RGB 카메라 해상도(`640×480` 기본값)에서 0.2m QR 코드가 일정 거리 이상이면 화면 내 차지하는 픽셀 수가 `pyzbar` 디코딩에 필요한 최소 모듈 픽셀 수(모듈당 약 2~3px)를 밑돌게 됨.
  2. **ROI 내에서도 유효 픽셀 부족**: `detect_qr()`에서 화면 중앙 60% 크롭 후 Otsu 이진화를 적용하더라도, 원거리 QR은 이진화 결과 자체가 뭉개져 경계선이 사라짐.
  3. **업스케일의 한계**: 멀티스케일(1x → 2x → 4x) 업스케일은 이미 뭉개진 픽셀을 보간(Interpolation)하는 것이므로, 원본 정보 자체가 손실된 경우에는 효과 없음.
  4. **cv2.QRCodeDetector fallback 오류**: `detectAndDecodeMulti` 메서드가 ROS Noetic 기본 OpenCV(4.2)에 미탑재(`AttributeError` 발생) → `detectAndDecode`로 교체 필요.

* **해결 과정**:
  | 단계 | 적용 내용 | 결과 |
  |------|-----------|------|
  | 1차 | GaussianBlur 제거, Otsu 이진화 활성화 | 부분 개선, 여전히 미인식 |
  | 2차 | 중앙 ROI 크롭 + 멀티스케일(1x/2x/4x) 업스케일 | 미인식 (원본 픽셀 손실이 근본 원인) |
  | 3차 | cv2.QRCodeDetector fallback 추가 | `AttributeError` 발생 (OpenCV 버전 불일치) |
  | 4차 | `detectAndDecodeMulti` → `detectAndDecode`로 교체 | fallback 오류 해결 |
  | **최종** | **로봇과 QR 코드 간 거리를 근접(~0.5m)으로 배치** | **인식 성공** |

* **결론 및 권장 배치 기준**:
  * `0.2 x 0.2` 크기의 QR 코드는 TurtleBot3 Waffle Pi 카메라 기준으로 **약 0.5m 이내 거리**에서만 안정적으로 인식됨.
  * Gazebo에서 QR 모델 배치 시 로봇 초기 위치(`X=0.0, Y=0.0`)로부터 **0.3m ~ 0.7m 전방**에 배치할 것을 권장.
  * 인식 거리를 늘리려면 QR 크기를 `0.2 → 0.4` 이상으로 확대하거나, 카메라 해상도를 높이는 방법을 검토해야 함.
