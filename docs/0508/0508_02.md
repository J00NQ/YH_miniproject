## 2. 캘리브레이션 적용으로 얻는 효과

### 2.1 렌즈 왜곡 보정 (Distortion Correction)
카메라 렌즈는 물리적 특성상 **방사 왜곡(Radial Distortion)** 과 **접선 왜곡(Tangential Distortion)** 을 발생시킵니다.
왜곡이 보정되지 않은 이미지에서는 직선이 곡선으로 찍히고, QR 코드의 꼭짓점 4개가 실제 위치와 달리 안쪽 또는 바깥쪽으로 휘어 검출됩니다.
`cv2.undistort()`를 적용하면 픽셀 좌표가 보정되어 QR 코드 경계선이 직선으로 복원됩니다.

| 상태 | 증상 |
|---|---|
| 보정 전 | QR 꼭짓점이 실제보다 안쪽/바깥쪽으로 편향 → `polylines` 바운딩 박스가 틀어짐 |
| 보정 후 | 픽셀 좌표가 핀홀 카메라 모델 기준으로 정렬 → 바운딩 박스가 QR 코드에 정확히 밀착 |

### 2.2 QR 코드 인식률 향상
`pyzbar`는 QR 코드 패턴의 직각성(Finder Pattern)을 기반으로 디코딩합니다.
왜곡된 이미지에서는 Finder Pattern의 각도가 틀어져 디코딩 실패율이 높아지는데, 왜곡 보정 후 인식률이 개선됩니다.
특히 카메라와 QR 코드 사이의 각도가 클 때(비스듬한 접근) 효과가 두드러집니다.

### 2.3 물리 좌표 변환 정확도 향상 (PnP 연계)
`cv2.solvePnP()`로 QR 코드의 3D 위치를 추정할 때 카메라 내부 파라미터 행렬(camera matrix)이 필수입니다.
캘리브레이션 파라미터를 `/camera/rgb/camera_info` 토픽에서 동적으로 수신하면, 하드코딩된 근사값 대신 시뮬레이터가 실제로 사용하는 정확한 값을 사용하게 됩니다.
이 정확도 차이가 거리 측정 오차에 직접적으로 영향을 줍니다.

## 3. 주요 수정 내역 (`vision_recognizer_node.py`)

### 3.1 CameraInfo 구독 추가
```python
from sensor_msgs.msg import Image, CameraInfo

# __init__ 내부에 추가
self.camera_matrix = None
self.dist_coeffs = None
rospy.Subscriber('/camera/rgb/camera_info', CameraInfo, self.camera_info_callback)
```

### 3.2 camera_info_callback 메서드 추가
```python
def camera_info_callback(self, msg):
    """카메라 내부 파라미터를 토픽에서 동적으로 수신"""
    if self.camera_matrix is None:
        self.camera_matrix = np.array(msg.K).reshape(3, 3)
        self.dist_coeffs   = np.array(msg.D)
        rospy.loginfo("카메라 캘리브레이션 파라미터 수신 완료.")
```
- `msg.K`: 3×3 내부 파라미터 행렬 (초점거리 fx, fy / 주점 cx, cy)
- `msg.D`: 왜곡 계수 벡터 (k1, k2, p1, p2, k3)
- 최초 1회만 저장하고 이후 콜백은 무시 (Gazebo 환경에서 파라미터는 고정값)

### 3.3 image_callback 내 왜곡 보정 삽입
```python
def image_callback(self, data):
    # ... (기존 bridge 변환 코드) ...
    cv_image = self.bridge.imgmsg_to_cv2(data, "bgr8")

    # 캘리브레이션 파라미터 수신 완료 시 왜곡 보정 적용
    if self.camera_matrix is not None:
        cv_image = cv2.undistort(cv_image, self.camera_matrix, self.dist_coeffs)

    # 이후 기존 전처리 → QR 디코딩 → 시각화 순서 유지
    preprocessed_img = self.preprocess_image(cv_image)
    # ...
```
- 보정은 컬러 원본 이미지에 적용한 뒤 기존 전처리 파이프라인으로 전달
- 파라미터 수신 전에는 보정 없이 기존 로직으로 동작 (안전한 폴백)

### 3.4 보정 전/후 비교 창 추가 (디버깅용)
```python
# image_callback 시각화 블록에 추가
if self.camera_matrix is not None:
    raw_image = self.bridge.imgmsg_to_cv2(data, "bgr8")  # 보정 전 원본
    cv2.imshow("Raw (Distorted)", raw_image)
cv2.imshow("Robot Camera Vision (Undistorted)", cv_image)
```

## 4. 실행 방법 (테스트)
```bash
# 1. 시뮬레이션 환경 실행
roslaunch qr_logistics_robot logistics_world.launch

# 2. 업데이트된 비전 인식 노드 실행
rosrun qr_logistics_robot vision_recognizer_node.py
```
- 노드 시작 후 터미널에 **"카메라 캘리브레이션 파라미터 수신 완료."** 로그가 출력되면 왜곡 보정이 활성화된 상태입니다.
- 디버깅 창을 활성화하면 보정 전(Raw)/후(Undistorted) 두 창을 나란히 비교할 수 있습니다.
- Gazebo 기본 카메라는 왜곡이 거의 없으므로 육안 차이는 작으나, 실제 물리 카메라로 전환 시 효과가 명확하게 나타납니다.
