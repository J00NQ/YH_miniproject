# 모듈 7: 경로 탐색 네비게이션 뼈대 설계

이 문서는 2일차 마지막 과정으로, 모듈 6의 실시간 비전 노드로부터 발행된 `/target_logistics_info` 토픽(목적지 좌표)을 구독하여, ROS의 자율주행 패키지인 `move_base`에게 이동 명령(Goal)을 내리는 액션 클라이언트 노드의 작성을 다룹니다.

---

## 1. 개요
* 로봇 자율주행 명령의 핵심은 ROS의 **Action(액션) 통신**입니다.
* 비전 노드가 "A구역으로 가라!" 라고 목적지를 주면, 이 노드는 `[3.0, 3.0]` 이라는 좌표를 추출하여 `MoveBaseGoal` 이라는 규격화된 메시지로 예쁘게 포장한 뒤 Navigation 스택으로 던져줍니다.
* 아직 SLAM(지도 매핑)과 Navigation 스택 구동을 진행하지 않았으므로, 이번 모듈에서는 **좌표 데이터를 주행 명령으로 변환하는 통신 뼈대 로직**까지만 검증합니다.

---

## 2. 경로 탐색 노드 권한 부여

새롭게 작성된 `path_planner_node.py`를 리눅스로 동기화하고 실행 권한을 부여합니다.

```bash
chmod +x ~/catkin_ws/src/qr_logistics_robot/scripts/path_planner_node.py
```

---

## 3. 실행 및 검증 (테스트)

모듈 6에서 진행했던 실시간 비전 연동 상태에서 터미널을 하나 더 열어 진행합니다.

### [터미널 1~4] 기존 환경 유지
* Gazebo, RViz, Teleop(키보드 조종), Vision Node(모듈 6)가 모두 켜져있는 상태로 둡니다.

### [터미널 5] 경로 탐색 제어 노드 실행
새 터미널을 열고 파이썬 노드를 실행합니다.
```bash
cd ~/catkin_ws
source devel/setup.bash
rosrun qr_logistics_robot path_planner_node.py
```

### ✅ 테스트 방법 및 성공 기준
1. 터미널 5를 켜면 처음 5초간 대기하다가 `[WARN] Navigation 서버를 찾을 수 없습니다. (통신 뼈대 테스트 모드로 전환합니다.)` 라는 로그가 뜹니다. (정상입니다. 아직 주행 서버를 켜지 않았기 때문입니다.)
2. 다시 **터미널 3(키보드 조종 창)**에서 로봇을 회전시켜 **로봇의 시야에 QR 박스가 들어오도록 쳐다보게 합니다**.
3. **터미널 5 (경로 탐색 노드)** 창에 다음과 같은 로그가 뜨면 완벽하게 성공입니다!
   ```text
   [INFO] [...]: >>> [A_zone] 구역으로 주행 명령을 하달합니다! (목표 좌표: X=3.0, Y=3.0)
   [INFO] [...]: --- 주행 목표(Goal) 가상 전송 완료! (Navigation 스택 가동 시 로봇이 즉시 출발합니다) ---
   ```

이 로그가 확인된다면 **"카메라 인지 -> 데이터 해독 -> 주행 목표 하달"** 로 이어지는 무인 물류 로봇 시스템의 대동맥이 완성된 것입니다!
