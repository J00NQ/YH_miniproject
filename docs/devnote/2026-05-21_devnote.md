## 이슈

### qr코드 오인식 문제
- 서로 다른 qr코드 두 개를 근처에 두면 의도와 다른 qr코드를 인식
- 

### 1차 테스트
#### DB 연결 오류
- 원인:
  - path_planner_node.py에서 sqlite3.connect(db_path)를 사용했을 때
    - 오류: SQLite objects created in a thread can only be used in that same thread.
- 해결:
  - sqlite3.connect(db_path, check_same_thread=False)로 수정

#### 경로탐색 최적화 문제 (미해결)
- 좌표를 인식하고 목적지 경로를 발행하는 데는 성공하였으나, 최적의 경로로 주행하지 못하고 초기에 목적지로부터 멀리 떨어진 곳으로 이동하는 문제가 발생
- 한동안 멀어진 후 목적지까지 도착


### 2차 테스트

#### 상황
- 1차 테스트시 문제점인 여러개의 출발점 QR코드를 DB로 단일화하여 진행 중, 1번 목적지 도달 후 발생한 로그

#### 버그 1 — cv2.QRCodeDetector 크래시 (수정 완료)
- 원인:
  - `vision_recognizer_node.py`의 pyzbar fallback에서 `detectAndDecode()` 호출 시
  - OpenCV 4.2.0 내부에서 QR 윤곽 면적이 0인 경우 `cv2.error` 예외 발생
  - 예외가 catch되지 않아 `image_callback` 전체가 크래시
- 해결:
  - `detectAndDecode()` 호출을 `try-except cv2.error`로 감싸고, 예외 발생 시 빈 결과 반환

#### 버그 2 — START QR 로그에 "임무 ID: Unknown" 출력 (수정 완료)
- 원인:
  - 단일 START QR 포맷이 `{"type":"START"}`로 변경되어 `id` 필드가 없음
  - `logistics_info.get('id', 'Unknown')` → 항상 'Unknown' 반환
- 해결:
  - START 타입 로그에서 id 출력 제거
  - `"목적지는 orders DB에서 결정됩니다."` 메시지로 변경

#### 참고 — Library QUIRC is not linked (무시 가능)
- pyzbar가 QUIRC 라이브러리 없이 빌드된 환경에서 출력되는 경고
- 동작에 영향 없음
