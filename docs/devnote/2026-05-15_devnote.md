# 미니프로젝트 3일차 (2026.05.15)

## 개발 목표
기존 물류 창고 환경에서 **병원 시뮬레이션 월드**로 전환하고, 단일 QR 방식에서 **START/ARRIVAL 이중 QR 기반 자율주행** 시나리오로 고도화.

---

## 개발 내역

### [작업 1] 병원 월드 환경 구축
- `turtlebot3_hospital_sim` 오픈소스(MIT)에서 `hospital.world` 및 `models/hospital/` 추출, 패키지에 직접 통합 (경량화 구성)
- `hospital_world.launch` 신규 작성: 로봇 초기 스폰 위치 `(-2.0, 0.0)` → `(0.0, 0.0)` 변경
- 원작자 MIT 라이선스 파일 `models/hospital/LICENSE`에 원본 보존

### [작업 2] START/ARRIVAL QR 가제보 모델 자동 생성 스크립트
- `generate_qr_models.py` 작성: 스크립트 1회 실행으로 `qr_start`, `qr_arrival` 두 가지 Gazebo SDF 모델 자동 생성
- JSON 포맷을 경량화(`taskId/taskName` → `id/name/tgt/ARR`)하여 QR 버전(밀도)을 낮추고 모듈당 픽셀 크기를 확보
- QR 물리 크기: `0.2 x 0.2` (터틀봇 스케일 기준 1/4 크기)

### [작업 3] 비전 인식 노드 업데이트 (`vision_recognizer_node.py`)
- **퍼블리셔 `latch=True` 추가**: 노드 시작 순서와 무관하게 `path_planner_node`가 메시지를 수신할 수 있도록 보장 (비래칭 토픽으로 인한 메시지 유실 버그 수정)
- **GaussianBlur 제거**: 소형 QR에 강한 블러를 적용 시 픽셀 경계가 뭉개져 `pyzbar` 인식 실패 → 블러 처리 제거
- **Otsu 이진화 활성화**: CLAHE 이후 적응형 이진화로 흑백 경계를 선명하게 복원
- **중앙 ROI 크롭 + 멀티스케일 업스케일**: 화면 중앙 60% 크롭 후 1x → 2x → 4x 순으로 업스케일하여 모듈당 픽셀 수를 인위적으로 늘려 `pyzbar` 인식률 향상
- **`cv2.QRCodeDetector` fallback 추가**: `pyzbar` 전부 실패 시 OpenCV 내장 QR 디코더로 2차 시도
  - `detectAndDecodeMulti` (OpenCV 4.5.1+) → `detectAndDecode` (OpenCV 4.2, ROS Noetic 기본)로 교체 (`AttributeError` 버그 수정)
- **ROI 탐색 범위 시각화**: OpenCV 창에 주황색 박스로 현재 분석 중인 ROI 영역 표시
- **바운딩 박스 좌표 역변환**: ROI 크롭 + 업스케일 좌표계를 전체 이미지 좌표계로 역변환하여 QR 위치가 화면에 정확히 표시되도록 수정

### [작업 4] 경로 계획 노드 업데이트 (`path_planner_node.py`)
- **START/ARR 타입 분기 처리**: `type` 필드 기반으로 START(주행 시작)와 ARR(배송 완료) 로직 분리
- **배송 완료 처리**: `ARR` 수신 시 Task ID 대조 후 일치하면 `current_goal_id = None`으로 초기화하여 대기 상태 전환
- **구버전 호환 유지**: 기존 `destination/target_coordinates` 포맷도 처리 가능하도록 else 분기 보존
- **로그 메시지 개선**: `name` 필드를 활용해 `[책상3(으)로 이동] 임무를 시작합니다!` 형태로 출력

## 이슈 및 해결

이슈 상세 내용은 [`0515_issues.md`](../0515/0515_issues.md) 참고.

| 이슈 | 원인 | 해결 |
|------|------|------|
| VMWare 파일 전송 오류 | 드래그 앤 드롭의 대용량 파일 전송 불안정 | ZIP 단일 파일 전송 or `git pull` 동기화 |
| 소형 QR 인식 실패 (고밀도) | JSON 길어서 QR 버전 상승 → 픽셀 뭉개짐 | JSON 경량화 + GaussianBlur 제거 + Otsu 이진화 |
| QR 인식 거리 한계 | 원거리에서 픽셀 수 부족으로 디코딩 불가 | ROI + 멀티스케일 업스케일 + 배치 거리 단축(~0.5m) |
| `detectAndDecodeMulti` 오류 | OpenCV 4.2(ROS Noetic)에 미탑재 | `detectAndDecode`로 교체 |
| 메시지 유실 (노드 시작 순서) | 비래칭 토픽으로 늦은 구독자 수신 불가 | 퍼블리셔에 `latch=True` 추가 |
